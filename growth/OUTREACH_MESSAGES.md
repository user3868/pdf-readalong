# PDF Readalong：可复制的获客消息与渠道 SOP

> 本文件是已准备、尚未发送的素材。**任何文案不得说“网页版已经上线”“6元购买已开放”“兼容所有PDF”。** 演示视频 URL 暂缺；外部发帖前请放入自己已检查无错的真实演示。
> 目标：区分“PDF→高亮讲解视频”的制作型需求与“直接听读 PDF”的消费型需求。

## 01. B站视频：先卖使用场景，不卖 AI 万能

### A1 教师/课程制作者：视频标题（择一）
- 《手里只有 PDF 讲义，能不能直接生成逐行高亮、自动配音的课程视频？我写了一个开源工具》
- 《不录屏不逐句加字幕，试着把两页 PDF 讲义直接做成讲解视频｜真实输出》
- 《做微课最累的可能不是讲课，是配音和高亮对时间轴：我做了个小工具》

**前10秒真实拍法：** 一分屏左边展示 PDF 原文，一分屏右边直接展示自己工具输出的同一页讲解视频。实际画面、音画同步截图，标明样本仅2页，不要隐藏错位或演示替代品。

**后20秒：** 展示“上传文本型 PDF → 选择音色 → 输出 MP4 + MP3 + SRT”。如演示视频不含完整真实操作，标注“效果演示，流程另附”。

**结尾CTA：** “源码在 GitHub 完全开放。我在找最近一个月真正做过讲义视频的老师，帮我看一次真实文档能否正常工作；只想听表扬不用来，最想听它哪里不够用。评论‘讲义’并写一下你制作课程的类型，我会按实际需求联系。正式一键包仍在发布核验。”

**评论区置顶：** “目前 Windows / 带文字层 PDF 更适合。扫描 PDF、公式、复杂双栏可能失败；在线朗读会连接语音服务。正在招募真实样本，禁止提交保密文档。源码：https://github.com/user3868/pdf-readalong”

### B1 听读者：试错导向标题
- 《看 PDF 看累了，我把一份文档变成可听的同步高亮视频；这能替代真正的 PDF 阅读器吗？》

**结尾CTA：** “现在做的是转成视频，不是手机上点击一句直接跳读的阅读器。如果你每周都看长 PDF，告诉我你真正要的是‘导出视频’还是‘实时边看边听’，我会先按真实需求决定要不要做网页版。”

**正文：**

我现在最缺的不是功能清单，而是 10 位确实经常把 PDF 讲义做成视频的人，想问三个具体问题：
1) 最近一个月实际制作过几条？原工作流在哪一步最费时间？
2) 为什么需要保留原 PDF 页面、而不是重做 PPT 或用 AI 改写内容？
3) 如果你愿意用一份有权使用、无保密内容的 PDF 试一次，最容易暴露哪个问题？

项目：https://github.com/user3868/pdf-readalong

欢迎明确指出这是不是一个没必要的视频形式；**只接受具体使用场景，不把点赞当需求验证。**”

## 04. 精准接触到潜在用户时的第一句话

**A 制作者：**
“看到你在聊给讲义视频配音/字幕。我自己做了个保留 PDF 原页并逐行高亮朗读的小工具，想确认一个实际问题：你最近一个月有没有把 PDF 讲义做成视频？最麻烦的是录屏、配音、对齐字幕，还是其实只用 PPT 就够了？如果不方便回答没关系，我不是批量发广告。”

**B 阅读者：**
“看到你在讨论边听边看 PDF。我做了一个可导出高亮跟读视频的开源原型，但目前还不是实时交互 PDF 阅读器。我想分清一个需求：你更需要把长文档变成音频带走，还是在手机/电脑上听一句就能跳回那句原文？你上周有实际遇到吗？”

**拿到具体回复后再邀请：**
“谢谢，你描述的[填写对方真实问题]很具体。我这边有个已经验证过小样例的原型，但还不能承诺复杂 PDF 成功。你愿意拿一份**自己有权使用、无隐私**的文字 PDF 让我帮你转一次，直接看看结果是否够用吗？不用付费，失败也会给你明确结果。”

**有效体验后验证付款：**
“源码免费可用。对你这种情况，如果一键免配置包最终按 6 元卖、无一对一远程安装，你会自己购买，还是宁愿直接用源码？以后如需要我替你代转视频，可以按一单明示价格单独报价。还没完成付费包发布检查，不收预付款。”

**拒绝以后：**
“明白。为了区分不是刚需、效果不达标还是不信任软件，能告诉我这次最核心的一个原因吗？只有这个问题，不继续打扰。”

## 05. 逐条筛线索，不要见人就问

**A 目标用户资格：** 最近30天至少做过一份视频；有自己的讲义/PDF；会描述具体工具流程；可举出最不满一步。否则不计为合格目标。只做 PPT、不想保留原 PDF 的用户属于市场探索，不计A有效目标。

**B 目标用户资格：** 最近7天真正读过两份或以上PDF；能具体说边看边听时何处需要跳读，或有明确手机/通勤场景。只听小说/新闻的人不计B有效目标。

**阶段记录：** 首次看见（线索） -> 明确资格 -> 已发起真实接触 -> 有效回复 -> 真实文档测试 -> 结果可用 -> 真实付款 -> 再次使用。每一步附日期、来源链接、用户原话。主动招募与自然流入必须分开。

**内部验证阈值（不是成功保证）：** 20A/10B真实接触后，若有效回复不足3，优先改筛选条件和文案；若完成5次试用有3次不合格，优先修交付而非加营销；若6次有效体验仍零付款，先分析拒绝原因与定价/交付，不凭一次小样本否定市场。对陌生用户的第一笔真实付款是很好的推进信号，但不是PMF。

## 06. 禁止做的事
- 用机器人在评论区刷同样的话、抓取个人联系方式、伪装普通用户推广自己的项目。
- 把其他开发者的产品帖当作“30个可私信客户”的名单。
- 没有成功的样例就写“已适配所有 PDF”；虚构付费订单/付款意愿。
- 让用户直接把涉密 PDF、财报内部文件、学生信息发到公开 GitHub Issue。
- 在二进制分发许可和服务条款没解决前收“预售”款，或写“本地离线 TTS 已完成”。
